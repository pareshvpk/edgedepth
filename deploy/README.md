# Compiling EdgeDepth to a Hailo-8 HEF

The shipped HEF is `release/EdgeDepth/hailo8/EdgeDepth_hailo8.hef`.
The build log, bandwidth figures and emulator scores are in
[`../release/EdgeDepth/hailo8/COMPILE_NOTES.md`](../release/EdgeDepth/hailo8/COMPILE_NOTES.md).

## Toolchain

- Hailo Dataflow Compiler **3.34** (Linux x86_64). The 5.x line dropped
  Hailo-8, so a 5.x wheel cannot build this target.
- The DFC is a login-gated wheel from the Hailo Developer Zone
  ("Hailo Dataflow Compiler - Python package (whl)"). Install it in its own
  venv, e.g. `~/.venvs/hailo-dfc3`. `install_dfc.sh` scripts the install, but
  its final check expects a 5.x wheel with `hailo15h`. For 3.34, follow the same
  steps and confirm that `hailo8` is supported.
- Always run the DFC through `deploy/hailo-py`. It clears an inherited
  `PYTHONPATH` (e.g. ROS) that would shadow the DFC's pinned
  numpy/protobuf/tensorflow.

## Build

```bash
export HAILO_VENV=$HOME/.venvs/hailo-dfc3
B=deploy/build_hailo8_edgedepth
COMMON="--hw-arch hailo8 --onnx release/EdgeDepth/EdgeDepth.onnx --build-dir $B --float-ref 0.987,1.067,4.53"
./deploy/hailo-py deploy/dfc_flow.py parse $COMMON --opt-level 1
echo "model_optimization_config(checker_cfg, policy=disabled)" >> $B/hailo_stereo.resolved.alls
./deploy/hailo-py deploy/dfc_flow.py optimize $COMMON
./deploy/hailo-py deploy/dfc_flow.py emulate  $COMMON
./deploy/hailo-py deploy/dfc_flow.py compile  $COMMON --compiler-effort 0 --no-width-split \
    --hef $B/EdgeDepth_hailo8_e0nws.hef
```

Compiling takes about 9 minutes on the laptop and produces 7 contexts and a 23.16 MB HEF.
`--no-width-split` is required: without it, context 3 hits the 1 h mapping watchdog. Run long steps
under `script -q -c "..." /dev/null > log` so output flushes live.

## Why a script instead of the CLI

- **Two inputs.** `hailo optimize --calib-set-path` takes one path, but the
  graph has `left` and `right`. The Python API takes a dict keyed by input
  layer, which keeps the calibration pairs paired.
- **Layer names are only known after parsing.** `dfc_flow.py parse` resolves
  them and writes `<build-dir>/hailo_stereo.resolved.alls`.
  `hailo_stereo.alls` records why each compile decision was made: on-chip
  normalization, the soft-argmin index ramp kept at 16-bit, and the
  optimization level.

## Calibration set

`artifacts/calib_kitti_{left,right}.npy`: 64 KITTI pairs, uint8 NHWC
368×1232, generated by `src/make_calib.py`. They are not committed (the KITTI
licence is CC BY-NC-SA).

## Input convention

The ONNX takes ImageNet-normalized **NCHW float**. The model script prepends
normalization layers, so from `optimize` onward the network takes **raw uint8
NHWC 0..255**. The emulator therefore needs different data per context:

| context | input |
|---|---|
| `SDK_NATIVE` | normalized NHWC float |
| `SDK_FP_OPTIMIZED`, `SDK_QUANTIZED` | raw uint8 NHWC |

`dfc_flow.py emulate` picks the right one per context. The constants
`[123.675, 116.28, 103.53] / [58.395, 57.12, 57.375]` are `src/data.py`'s
`MEAN`/`STD` × 255.

## Results

| | EPE masked | EPE official | D1 official |
|---|---|---|---|
| fp_optimized (emulator) | 0.987 px | 1.067 px | 5.06% |
| int8 (emulator) | 1.240 px | 1.329 px | 6.32% |
| int8 (Hailo-8 on Pi 5) | 1.372 px | 1.437 px | 6.69% |

On-device runs: [`pi/README.md`](pi/README.md).

## Known limitation

The HEF outputs disparity as uint8 (241 levels of 0.651 px). One step is 0.17 m
of depth at 10 m but 2.9 m at 40 m, so far-range point clouds band. A 16-bit
output layer at compile time is the candidate fix.
